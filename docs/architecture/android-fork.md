# Android fork (FUTO Keyboard, branch `main`)

Current state of the changes made to FUTO Keyboard in `android/` (its own repository, `Atabold/atabold-keyboard-android`, branch `main`). How to build it and the toolchain are in [dev-environment.md](dev-environment.md); the rules being implemented are in the spec, sections 4, 5 and 9. In this document "the user" is the project's author.

Convention: new code lives in the package `org.futo.inputmethod.latin.kbfr` (`java/src/org/futo/inputmethod/latin/kbfr/`), and every edit to a FUTO file is marked with a `kbfr fork:` comment, so the fork stays easy to rebase on FUTO's `master`.

| Diff and explanations (spec 5.1 point 4) | `kbfr/WordDiff.kt`, `kbfr/Correction.kt` | Tokens are words, whitespace runs and single other characters (so `la université` → `l'université` keeps `université`); every character lands in a token, so accepting everything gives exactly the model's result and rejecting everything the original. Above 4 M cells the middle becomes one change (bounded memory). An edit claims a change when a whole-word occurrence of `edit.from` in the original, or of `edit.to` in the result, overlaps it. Each change then goes to the most specific edit that claims it (shortest `from` + `to`): the model copies some context into `from`/`to`, and a context that reaches a nearby error must not tie two errors to one checkbox. That is the likely cause of two errors under one checkbox in Google Docs in an early build, when each claiming edit still merged its changes into one group. The changes of one edit form one group with one checkbox; an edit left with no change of its own is shown in the group of the first change it claims. |

## Checked and left as is

- **Crash reports (ACRA, stable flavor):** off in debug builds. In release they are **opt-in** (see the "Crash reports" row of the table above): until the user turns the switch on, a crash opens no dialog. When on, after a crash a dialog offers to email a report to FUTO; nothing is sent without the user. With logs stripped, the report holds the stack trace, device data and settings values, not typed text.
- **Bug viewer:** keeps bugs in memory. The clipboard manager used to copy its whole file into a bug report on I/O errors; that code is gone with the file.
- **Screenshot helper** (`ScreenshotHelper.kt`): only active when "save screenshots" is on; that setting has no UI any more and defaults to off, and its callback ignores screenshots anyway.

## Deviations from the spec

- **No source app in the mask.** Spec 5.5 asks for "`••••••` + source app". Android does not tell a keyboard which app put a clip on the clipboard, so the mask is just `••••••`.
- **Copied in a blocked context** is judged by the field the keyboard is serving at the moment of the copy. When the copy happens outside any text field, that is the last field used; password managers set `EXTRA_IS_SENSITIVE` themselves, and the heuristic catches most passwords and codes anyway.
- **History duration:** FUTO's slider in hours (1–336) is kept, default 1 hour, instead of the spec's 1 min / 10 min / 1 h choice. Since the history is RAM-only, everything also disappears when the keyboard process stops.
- **The contaminated field (R3) follows the field's text** (decided with the user). Spec R3 ends contamination when the user moves to another field. Messaging apps use one field for every chat, so on the phone the first version kept the lock in every chat and dropped it in the chat that still held the pasted text. Now the lock is on while the field contains the pasted text; only a fingerprint of that text is kept (HMAC with a random key of the process).
- **R3 only sees pastes made from the keyboard** (user's choice): the clipboard history, the chip, the Paste action and the text-edit panel. A paste from the app's own menu (long press → Paste) is invisible to the keyboard; only the check of spec 5.6 covers it.
- **Secrets are recognised only by known prefixes and random look** (user's choice). With "block" as the default, the broader clipboard heuristic of 5.5 would also stop model names, file names and codes such as `claude-opus-4-1-20250805`. The price: a human-made password like `Elizabeth2024Paris!` is not recognised.
- **"Ask" and "confirm before sending" use the panel**, which opens on a confirmation step before anything is sent. The spec does not say where to ask.
- **"Confirm above N characters"** has its N as a slider of 100–4000, default 1000; the spec gives no default.
- **Traduire always shows the panel**: the insertion setting is in the Corriger / Améliorer section of spec 6. The same holds for **Format**.
- **Automatic formatting with sensitive data** (user's choice). Nobody can be asked in the middle of a dictation, so a category set to "ask" keeps the text as dictated, like "block", with the notice. "Confirm before sending" does not apply: turning automatic formatting on is the consent, and with "always" it would never run.
- **Undo after automatic formatting** (user's choice): "Formatted · Undo" puts back the dictated text. The spec does not ask for it; the user does not see what the model changed.
- **The Voice settings section is called "Voice / Format"**: its style and grammar options also apply to the manual Format.
- **The 60 s of a sensitive clip count while the phone is awake.** The timer is a coroutine delay on the main thread, whose clock stops in deep sleep, so with the screen off a clip can stay longer. Already true since M2.
- **The backend URL is fixed in the build** (security review, agreed with the user). Spec R5 talks of "the host given in the settings". An editable URL let anyone with the unlocked phone for a few seconds, or a settings backup prepared by someone else and imported (FUTO's import replaces the whole DataStore), point the keyboard at their own server. That server could forward each signed request to the real backend within the ±30 s window, because the signed string does not contain the host, and return the real answer, or a changed one: everything kept working, no alert fired, and the panel shows no host. Now `BackendClient` only ever gets `BuildConfig.KBFR_ENDPOINT`, shown read-only in the settings. Moving to another backend needs a new build, like the certificate hash. Not done: putting the host in the signed string, which would also need a backend deploy.
- **No QR code for the public key** (spec 6 asks text, QR and Share): decided with the user, to avoid a QR library. Share and Copy are enough to get the key to the PC once. Copying puts the key through the keyboard's own clipboard rules: base64 looks like a secret, so it is masked and cleared after 60 s.
- **Only the phone key is registered** (decided with the user). The PC development key is re-registered only temporarily, e.g. to run the prompt evaluation (`tools/register-device.mjs --dev`, then the phone key again).
- **Warm up feedback is an emoji on the toolbar button** (🔥 → turning clock → ✅), chosen by the user; spec 5.8 only asks for a loading indicator and a ✓ for about 2 s. Errors go to the status strip.
- **"Wi-Fi only" shows no lock.** The network changes all the time, so it is checked when the action is tapped, and the reason appears in the status strip.
- **Short messages** (block reasons, errors of spec 5.7) appear in a strip above the toolbar instead of a toast, the same place as the integrity banner.
- **The panel does not show the backend host** (spec 5.1 and 5.7 ask for "→ <host>"): removed at the user's request, so screenshots and people nearby do not see the endpoint. It stays in the settings only.
- **Corriger is not disabled on an empty field** (spec 5.1 point 1): knowing that would mean reading the field on every keystroke. A tap on an empty field says "No text to correct".
- **Explanations are always visible** in a list under the diff, one row per change group with its checkbox, instead of appearing when a change is tapped: easier to read for learning, and the accept/reject is on the same row.
- **"Accept all" inserts the whole result at once**; "Insert" inserts only the checked groups. All groups start checked.
- **Undo ends when the field changes**, detected by `packageName/fieldId` at `onStartInput`: a restart of the same field keeps it. The strip decision (a line above the toolbar, not the panel staying open) was taken with the user.

## Verification

What was checked by hand on a phone (a Xiaomi on Android 16; release builds signed with the author's own key, and the dev build for the learning check), in the order of the milestones:

- **Learning and clipboard (M2).** In the dev build, a word typed in WhatsApp lands in the user-history file (`files/UserHistoryDictionary.<locale>.dict`) and the same kind of word typed in Chrome in no learning file (`run-as org.futo.inputmethod.latin.kbfr.unstable`). After installing the clipboard changes, no file with `clip` in its name exists in the dev build's storage.
- **Identity (M3).** The settings page opens (`am start ... --es navDest kbfr`) and shows the key created in the TEE and its key id; the APK has `INTERNET`, `usesCleartextTraffic=false` and `allowBackup=false`. Right after Regenerate, Test connection said "Not registered" and the Telegram alert arrived; after registering the new key with `tools/register-device.mjs`, the app showed the new key id and Test connection said "Registered". Regenerate stands in for the spec's uninstall + reinstall check: both replace the Keystore key with an unregistered one.
- **Warm up (M4, part 1).** In WhatsApp it goes 🔥 → clock → ✅ → 🔥. In Chrome and in a password field it is dimmed with a lock and a tap shows "App not allowed" or "Password or code field"; with Online off it is locked with "Online features off"; with Wi-Fi only on and Wi-Fi off it shows the Wi-Fi message; in airplane mode "Backend unreachable". The settings sections render and Test connection still says "Registered".
- **Corriger (M4, part 2).** In WhatsApp the panel shows the diff and the explanations; unchecking one group inserts only the others; "Corrected · Undo" restores the original and disappears when the field changes; a selection in WhatsApp is ignored. In Gmail only the selection is sent and replaced, and without one the whole body. Already-correct text gives "No errors found". Accept all and the "replace at once" mode work. In Google Docs a 150-character selection is read and replaced, and each error has its own checkbox. Chrome is locked; airplane mode gives "Backend unreachable".
- **English varieties.** With harmonise off, `I realized my favorite color is the colour of the ocean.` gives "No errors found" and the note colour → color with an unchecked box (the first build also showed the model's own change to "color", fixed by `keepAsWritten`); checking it previews and inserts "color"; unchecked, Insert is disabled. With harmonise on, "colour" is a `variant` change with its checkbox and explanation.
- **Améliorer, Traduire, checks before sending, R3 (M5).** The settings show confirm before sending, the seven sensitive-data rows with the spec's defaults, the Corriger / Améliorer and Traduire sections, and the 60 s line in the clipboard settings. Améliorer proposes "Style" changes, inserts, and shows "Improved · Undo". Traduire translates a text into French with Insert, and "Translated · Undo" restores the original; with "Translate into: English", French → English. An IBAN, a card and an `sk-proj-…` key stop the request with the category in the strip; `claude-opus-4-1` passes. An OTP opens the confirmation, where Cancel sends nothing and Send corrects; "Always" and "above 100 characters" ask as expected. R3: a first version kept the lock in another WhatsApp chat and dropped it on returning to the chat with the pasted code, which led to the content-based version; in that one the lock leaves on entering an empty chat, comes back in the chat that holds the code, a tap after deleting just the code corrects, and emptying the field lifts it. After 60 s FUTO's Paste no longer pastes the code, with the keyboard open and with it closed; temporary `println` diagnostics (since removed) showed the system clipboard read and cleared on time both ways.
- **Format and automatic formatting (M6).** The Voice / Format section shows its three rows with the defaults. Format in WhatsApp shows the diff with one checkbox per change; unchecking one inserts only the others, and "Formatted · Undo" restores the original. With automatic formatting on, the voice window shows "Formatting…", the formatted text goes in, and Undo puts back the dictated text. In an app that is not allowed (a browser) the dictation goes in with no "Formatting…" and no strip. The dictation model writes punctuation and capitals itself, so unformatted dictation can look formatted; the strip is the reliable sign. A dictated OTP goes in as dictated, with the sensitive-data notice, and in airplane mode the text goes in as dictated, with "Not formatted: Backend unreachable".
- **Backend URL fixed in the build.** The JVM tests pass and the release build is signed with the personal key (`apksigner verify`); its dex holds the URL and no longer the `kbfr_endpoint` key. On the phone, the settings show the URL read-only, Test connection says Registered and Corriger works.
